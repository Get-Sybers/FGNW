# slopMop v0.5.3 — range test results + accuracy cross-check

## 1. Environment

- **Binary**: `slopmop-v0.5.3-windows-amd64.exe` (8.5 MB, from GitHub release)
- **Deployed as**: `C:\slopmop-v5.3.exe` on konoha-ws1
- **Range**: FGNW Ludus cyber range (range_id JB, second_octet 1)
- **Host**: konoha-ws1 (10.1.10.21), Windows Server 2019
- **Artefact folder**: `C:\slopmop-capture` — 82 files (9 scripts, 70 outputs, 3 zips)
- **Watchlist**: `C:\slopmop-watchlist.json` — 8 entries (SLOPMOP-KALI-ATTACKER + STORM-0940)

## 2. What's new in v0.5.3 vs v0.5.0

Commits v0.5.0..v0.5.3 (16 commits across 3 minor releases):

### v0.5.1

- **Cross-drive outdir fix**: `within()` rewritten so an output folder on a
  different volume is accepted. Verified with `subst D:` simulation — v0.5.0
  rejected `D:\slopmop-output`, v0.5.1+ writes 10 files to it.
- **Parallelism**: `-cores <percent>` and `-memory <percent>` flags for resource
  limiting on shared machines. All processors used by default.

### v0.5.2

- **Linear report assembly**: report assembly made linear in file count
  (performance fix for large evidence sets).
- **SQLite store added then removed**: internal record store tried and backed
  out in the same release cycle.

### v0.5.3

- **Subject groups in Targeted**: entities grouped by type (Service, Runs, Task,
  Application, Tenant, Vault, Secret, Mailbox, Call, Archive) instead of a flat
  list.
- **AI-agent impact lowered to informational**: "Commands generated by an AI
  agent" moved from `[!]` medium to `[i]` informational. AML.M0020 and
  AML.M0022 mitigations follow.
- **Empty sections hidden**: sections with no content are omitted from the
  report (Intents section no longer appears as `none`).
- **Duplicate evidence removed**: impact and remediation sections deduplicated.
- **ISO-8601 timestamps**: timeline times normalised from `20261116_092151` to
  `2026-11-16T09:21:51Z`.
- **Overflow references**: long evidence lists say `and N more in the saved
  findings` pointing to the JSON output.
- **Unresolved shell variables**: `$variable` names kept as remediation targets
  instead of being dropped.

### False positives (unchanged from v0.5.0)

- **IP indicators**: 4/14 false positives (version strings `0.77.2.0`,
  `0.77.3.0`, `8.53.0.77` + subnet mask `255.255.255.0`)
- **Usernames**: 10/14 false positives (Windows groups/error fragments)
- **Masking over-aggression**: 2 cases (`smtp-password` name, `password reset`
  filter)

### False negatives (unchanged from v0.5.0)

- certutil T1140 not flagged as activity
- Registry Run key not a named activity
- MAC address not captured
- Hostnames in ad-recon log not attributed

### What improved

- **Subject groups in Targeted**: entities now grouped by type with the activity
  that acted on them. Vault, Secret, Mailbox, Task, Service, Application,
  Tenant, Call, Archive, Runs all have their own sections with evidence lines.
  This makes the section much more readable.
- **ISO-8601 times**: timeline timestamps are unambiguous (`2026-11-16T09:21:51Z`
  vs `20261116_092151`).
- **AI-agent impact at informational**: no longer inflates the medium count.
- **Empty Intents section hidden**: no confusing `none` output for datasets
  without ARTEX folders.
- **Overflow references**: instead of silently truncating evidence, the report
  says `and N more in the saved findings` directing the reader to the JSON.
